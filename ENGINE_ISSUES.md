# Запросы к движку headless-gui

Файл ведёт команда Go.Git для команды движка `github.com/oops1/headless-gui/v3`.
Здесь всё, чего проекту не хватает в движке или что в нём работает не так, как заявлено.
Проверено на версии **v3.16.2** (то, что закреплено в `go.mod`).

Формат записи: идентификатор, тип (**Ошибка** — заявленное поведение расходится с
фактическим, **Возможность** — поведения нет), что происходит, как воспроизвести,
зачем это Go.Git, какой обход применён сейчас. Обход в Go.Git снимается в том же
релизе, в котором поднимается версия движка.

Приоритет: **A** — блокирует запланированную функциональность, **B** — заметно
ухудшает результат, **C** — удобство.

## Ошибки

### GG-1. `DockPane Size` из XAML не доживает до раскладки — A

`<DockPane Size="260">` применяется до первого `SetBounds`, поэтому `clampSideSize`
режет значение до минимума, и стороны дока стартуют схлопнутыми.

Воспроизведение: загрузить XAML с `DockManager`, где у панели задан `Size`, вызвать
`engine.SetRoot`, снять кадр — ширина стороны равна минимальной, а не заданной.

Нужно: применять размеры сторон после первой раскладки; при нескольких панелях на
стороне брать максимум заданных `Size`, а не последнее значение.

Обход: `app.applyDockSizes` вызывает `SetSideSize` вручную после `SetRoot`.

### GG-2. `KeyBinding` в XAML не понимает функциональные клавиши — B

`widget.parseKeyName` разбирает одиночные буквы и небольшой фиксированный список,
поэтому `<KeyBinding Key="F5"/>` из XAML не срабатывает; из кода
`widget.InputBinding{Key: widget.KeyF5}` работает.

Нужно: разбор `F1`–`F24`, `Esc`, `Del`, `Ins`, `Home`, `End`, `PgUp`, `PgDn`,
`Enter`, `Tab`, `Space` и модификаторов к ним.

Обход: горячие клавиши вешаются из Go-кода (`app.wireHotkeys`).

### GG-3. Скрытый ребёнок не схлопывает строку `Grid` — B

`Visibility=Collapsed` (или `SetVisible(false)`) на единственном ребёнке строки
не пересчитывает высоту строки: остаётся пустая полоса. В `widget/grid.go`
раскладка не учитывает видимость детей.

Воспроизведение: `Grid` со строками `40 / * / 24`, скрыть виджет в первой строке —
полоса 40 px остаётся пустой.

Зачем: настройки «Показывать панель инструментов» и «Показывать строку состояния».

Обход: панель скрывается, полоса остаётся видимой пустой.

### GG-4. `MenuBar.SetSubItemText` не достаёт до третьего уровня — B

Текст пункта вложенного подменю (`MenuItem.SubItems`) менять штатно нечем:
`SetSubItemText(top, sub)` адресует только второй уровень. Сейчас это делается
записью в разделяемый срез из `Items()`, что держится на детали реализации
(«`Items()` копирует только внешний срез»).

Нужно: либо `SetItemText(path ...int)`, либо документированная гарантия, что
структуры из `Items()` можно менять на месте.

Зачем: смена языка интерфейса и галочки в «Вид → Панели/Тема/Язык».

Обход: мутация структур, полученных из `Items()`.

## Недостающие возможности

### GG-5. `MenuItem.Checked` — B

У пункта меню нет состояния «отмечен». Активная тема, язык и видимые панели
помечаются префиксом «✓ » в тексте, что выглядит самодельно.

Нужно: поле `Checked bool` (и, желательно, `RadioGroup string`), отрисовка галочки
слева от подписи, поддержка атрибута в XAML.

### GG-6. Замена и дополнение пунктов уже собранного меню — B

После `LoadUIFromXAML`/`AddMenu` состав меню менять нечем: нет `SetItems`,
`InsertItem`, `RemoveItem`, `Clear`.

Зачем: список языков динамический — пользователь кладёт свой JSON в каталог
переводов, и такой язык невозможно показать в «Вид → Язык».

Обход: в меню показываются только встроенные `en`/`ru`, объявленные в XAML;
остальные языки доступны только в диалоге настроек.

### GG-7. Загрузка ресурсов XAML из `fs.FS` — A

`LoadUIFromXAMLWithBase` умеет только каталог на диске, поэтому `Icon`, `Source`,
`BackgroundImage` нельзя брать из `embed.FS`.

Нужно: `widget.LoadUIFromXAMLFS(data []byte, fsys fs.FS)` (или `Options{FS}`).

Зачем: Go.Git — один самодостаточный исполняемый файл, ресурсов на диске нет.

Обход: иконки назначаются из Go-кода после загрузки XAML.

### GG-8. Публичная растеризация SVG — A

`widget/svg` разбирает документ, но отрисовка доступна только через `SVGIcon`.
Нужна функция вида `svg.Render(doc *svg.Document, w, h int, tint color.RGBA) *image.RGBA`.

Зачем: иконки тулбара, дерева и статусов файлов в цвет активной темы, из `embed`.

Обход: тулбар пока текстовый.

### GG-9. Измерение текста конкретным шрифтом — B

`widget.MeasureUIText` меряет шрифтом по умолчанию, а `DrawTextFont` рисует
указанным семейством. Пока это совпадает (Consolas не зарегистрирован и подменяется
дефолтным), но как только моноширинный шрифт появится, раскладка diff-виджета
разъедется: ширина колонок и горизонтальная прокрутка считаются по другому шрифту.

Нужно: `MeasureTextFont(text, family string, sizePt float64) int` и, желательно,
позиции символов (`MeasureRunePositions`) для попадания курсора и выделения.

Обход: расчёт по шрифту по умолчанию.

### GG-10. `DockManager`: разделение панелей на одной стороне — B

Две панели на одной стороне показываются вкладками; разделить их по вертикали
(как «Репозитории» над «Ветками» на макете заказчика) нечем.

Нужно: `<DockPane Stack="Split">` или `SplitSide(side, ratio)`; раскладка должна
переживать `SaveLayout`/`RestoreLayout`.

Обход: панели показываются вкладками.

### GG-11. `TreeView`: иконки, стиль узла, контекстное меню, drag&drop — B

Узлу нельзя дать иконку (`image.Image`), выделить текущую ветку жирным или цветом,
повесить контекстное меню и перетаскивать узлы мышью.

Зачем: дерево репозиториев (группы, репозитории, worktree, состояние) и дерево веток.

Обход: состояние показывается текстовыми префиксами («● », «⎇ »).

### GG-12. `DataGrid`: своя отрисовка колонки, событие прокрутки, виртуализация — B

Нет колонки с произвольным отрисовщиком (нужна для графа ветвлений), нет события
изменения прокрутки (подгрузка следующей порции журнала сейчас держится на выборе
строки в конце списка), не проверена работа на 100 000 строк.

Нужно: `DataGridTemplateColumn` с рисующим колбэком, `OnScroll`/`FirstVisibleRow`,
виртуализация строк.

Обход: граф — текстовая колонка «*»; догрузка по выбору строки рядом с концом.

### GG-13. Контекстное меню на строку таблицы и узел дерева — B

`SetContextMenu` есть у виджета целиком; нужен колбэк с данными строки или узла,
по которому меню собирается на месте.

Зачем: действия над файлом, коммитом, веткой.

### GG-14. Очередь вызовов в поток рендера — C

Нет `engine.Post(func())`. Приложение завело свою очередь и диспетчер, чтобы
обновлять виджеты из фоновых горутин.

Нужно: `Post`/`Invoke`, выполняемые в цикле рендера.

### GG-15. Локализация штатных диалогов через таблицы приложения — C

`MessageBox` и файловые диалоги переводятся своими ключами `dlg.*`; хотелось бы
подменять их из таблиц приложения (`{Loc}`), чтобы язык был один на всё окно.

### GG-16. `{Loc}` в заголовках колонок `DataGrid` — C

Заголовки колонок не участвуют в живом переключении языка: `{Loc}` в `Header`
разворачивается один раз при загрузке.

Обход: заголовки переустанавливаются из кода при смене языка.

### GG-17. Виджет тулбара — C

Нужен `ToolBar` с разделителями, режимом «только иконки» и переполнением;
сейчас используется `StackPanel` с кнопками.

### GG-18. `SetMinSize` для X11/Wayland — B

`window.SetMinSize` реализован только на Windows; на Linux окно можно сжать меньше
заявленного минимума 800×600.

Нужно: `WM_NORMAL_HINTS` для X11 и `xdg_toplevel.set_min_size` для Wayland.

### GG-19. Нативное отсоединение док-панели — C

`DockPane.OnFloatNative` объявлен, но ни один бэкенд его не назначает: панель
«отсоединяется» внутри холста, а не в окно ОС.
