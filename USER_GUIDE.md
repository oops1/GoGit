# Руководство пользователя

Это руководство — для тех, кто скачал архив с релизом Go.Git и запускает
программу впервые. Оно описывает только то, что реализовано в текущей версии;
пункты меню и настроек названы так же, как в самом интерфейсе.

## С чего начать

### Распаковка

Релиз публикуется архивом без установщика:

- Windows — `gogit-vX.Y.Z-windows-amd64.zip`: `gogit.exe`, `LICENSE`, `NOTICE`.
- Linux (amd64 или arm64) — `gogit-vX.Y.Z-linux-<arch>.tar.gz`: исполняемый
  файл `gogit`, `LICENSE`, `NOTICE`.

Распакуйте архив в любой каталог и убедитесь по `SHA256SUMS` со страницы
релиза, что файл не повреждён. Установка не нужна: `gogit.exe` (или `gogit`
на Linux, файл нужно сделать исполняемым — `chmod +x gogit`) запускается
прямо из распакованного каталога. Системный git не требуется — Go.Git
реализует его сам.

На Windows приложение собрано без консольного окна: `gogit.exe` открывает
сразу главное окно, отдельного окна терминала не будет.

### Первый запуск

При первом запуске каталог с настройками ещё не существует — Go.Git создаёт
его сам. Если файл настроек не читается (повреждён), он переименовывается в
`config.toml.bad-ГГГГММДД-ччммсс`, и появляется отдельное сообщение о том,
что настройки сброшены к значениям по умолчанию.

Дальше открывается главное окно с пустыми док-панелями — репозиторий ещё не
выбран. Первым делом добавьте или откройте репозиторий (см. ниже).

### Где лежат настройки и журнал

Все свои файлы Go.Git хранит в одном каталоге, отдельном от репозиториев:

- Windows: `%AppData%\Go.Git`
- Linux: `$XDG_CONFIG_HOME/gogit` (обычно `~/.config/gogit`)

Каталог можно переопределить переменной окружения `GOGIT_CONFIG_DIR` —
это удобно, например, чтобы запустить второй, полностью независимый профиль.

Файлы в этом каталоге:

| Файл | Назначение |
|---|---|
| `config.toml` | Настройки, список репозиториев и групп — без секретов |
| `layout.json` | Раскладка панелей и окон |
| `vault.bin` | Зашифрованное хранилище паролей, токенов и SSH-ключей |
| `known_hosts` | Подтверждённые ключи SSH-хостов |
| `gogit.log` | Журнал приложения |
| `i18n/` | Файлы дополнительных языков (см. «Настройки → язык») |

`gogit.log` — обычный текстовый журнал (`log/slog`), пишется всегда, без
переключателя в настройках. Подробнее о нём — в разделе «Если что-то пошло
не так».

## Добавление и открытие репозитория

Всё начинается с меню **Репозиторий**:

- **Добавить или создать...** — открыть существующий каталог с git-репозиторием
  или создать новый (`Открыть существующий` / `Создать новый`, с полем пути и,
  при создании, именем и флажком **Bare**).
- **Клонировать...** — отдельный диалог: URL репозитория, каталог назначения,
  ветка, глубина клона (обычный, поверхностный или частичный — «Поверхностный
  клон» и «Частичный клон» — отдельные флажки), «Включая подмодули». Кнопка
  «Проверить URL» опрашивает репозиторий и показывает число веток до старта
  клонирования.
- **Добавить группу...** — локальная группа в дереве репозиториев: репозитории
  и другие группы можно перетаскивать в неё мышью.
- **Искать репозитории...** — сканирует каталог на диске на предмет `.git` и
  позволяет добавить найденные репозитории все сразу.
- **Закрыть репозиторий** — снимает активный репозиторий, панели очищаются.

Открытые репозитории и группы показываются в панели **Репозитории** и
сохраняются в `config.toml` — при следующем запуске Go.Git сам откроет тот
репозиторий, что был активен при выходе.

## Панели

Между панелью инструментов и строкой состояния находится область
док-панелей: любую панель можно скрыть, перетащить к другой стенке окна или
отсоединить в отдельное окно операционной системы. Раскладка запоминается
между запусками; **Окно → Сбросить раскладку** возвращает панели на
исходные места.

### Репозитории

Дерево: группы → репозитории → их рабочие копии (worktree). Двойной клик по
репозиторию или worktree делает его активным. В контекстном меню — открыть в
файловом менеджере, открыть в терминале, переименовать, удалить из списка,
переместить в группу.

### Ветки

Дерево с разделами **Локальные** (текущая ветка выделена), **Удалённые** (по
каждому remote отдельно), **Теги** и **Stash**; если в репозитории есть
подмодули, они тоже показаны здесь. У локальной ветки со своим upstream виден
счётчик расхождения — `↑3 ↓1` (коммитов впереди/позади). Одиночный клик
выбирает ветку, двойной — переключается на неё (**Переключиться на эту
ветку**). Контекстное меню ветки — слить, перенести (rebase) текущую ветку
поверх выбранной, переименовать, удалить, отправить/получить именно эту
ветку, сравнить с текущей, посмотреть, где была ветка (reflog).

Меню «≡» в заголовке панели управляет сортировкой (по имени, по имени с
обратным порядком чисел, по времени коммита), группировкой веток по пути
(`foo/bar`, с вариантами «После последнего слэша» и «Кроме одиночных»),
показом внешних веток в разделах Git-Flow и выбором устаревших локальных
веток (тех, чей upstream исчез на сервере).

### Файлы

Таблица изменений рабочей копии и индекса: статус, имя, путь; строки
группируются на Staged / Unstaged / Untracked / Conflicts, есть фильтр по
имени и множественный выбор. Контекстное меню — подготовить (stage), снять с
подготовки (unstage), отменить изменения (discard), игнорировать, убрать из
репозитория, открыть, редактор индекса, история файла, «Кто менял строки»
(blame), разрешение конфликта для конфликтных путей. Выбор файла в этой
панели показывает его diff в панели «Изменения».

### Изменения (diff)

Двухпанельный просмотр различий с подсветкой строк и внутристрочных правок,
синхронной прокруткой и переключением видов «рядом» / «единым текстом»
(side-by-side / unified). Строку можно выбрать щелчком, диапазон — щелчком с
Shift; правый щелчок по выделению открывает «Подготовить выбранные строки»,
«Подготовить блок», «Отменить выбранные строки», «Отменить блок» — для
неподготовленных изменений — либо «Снять с подготовки выбранные строки» /
«…блок» — для уже подготовленных. Панель пуста, пока в «Файлах» или
«Журнале» ничего не выбрано.

### Журнал

Таблица коммитов с графом ветвления, сообщением, автором, датой и хешем;
неотправленные коммиты помечены отдельно. Подгружается по мере прокрутки.
Выбор коммита показывает его файлы и diff. Контекстное меню — переключиться
на этот коммит, создать ветку или тег здесь, cherry-pick в текущую ветку,
отменить коммит (revert), сбросить ветку на этот коммит, сравнить с текущей
веткой, скопировать хеш или сообщение, «Кто менял строки», «История этого
файла».

## Основные сценарии

### Клонирование

**Репозиторий → Клонировать...** → заполните URL (HTTPS, SSH, `git://` или
локальный путь), при необходимости выберите ветку, поверхностный или
частичный клон и каталог. Go.Git сам разбирается в протоколе, включая v2 с
откатом на v0, — системный git для клонирования не запускается.

### Коммит

В панели «Файлы» подготовьте нужные файлы (**Локально → Подготовить**), при
необходимости — построчно или по блокам прямо в панели «Изменения». Затем
**Локально → Зафиксировать...** (или кнопка «Зафиксировать» на панели
инструментов) открывает диалог коммита: сообщение, число подготовленных и
незакоммиченных файлов, флажки «Изменить последний коммит» (amend) и «Не
запускать хуки». Если в репозитории настроен `pre-commit`, `commit-msg` или
похожий хук, его вывод виден прямо в диалоге.

### Получение и отправка (fetch / pull / push / sync)

Кнопки на панели инструментов и пункты меню **Внешний репозиторий**:

- **Получить (Fetch)** — только забирает объекты и ссылки.
- **Получить и слить (Pull)** — fetch, затем слияние по стратегии из
  настроек (merge / rebase / ff-only).
- **Отправить (Push)** — отправляет текущую ветку; если upstream не задан,
  предложит выбрать remote. Push уходит на все `pushurl` внешнего
  репозитория по очереди, если их несколько.
- **Синхронизировать (Sync)** — fetch → pull → push одной кнопкой,
  останавливается на первом конфликте.

Все три операции показывают окно длительной операции с логом действий и
кнопкой «Отмена».

### Ветки, слияние и rebase

**Ветка → Переключить ветку...** — выбор локальной ветки или создание новой
от удалённой с сразу включённым отслеживанием. **Слить...** и **Перенести
текущую ветку...** (rebase) в том же меню открывают диалоги с пояснением,
что именно произойдёт (перемотка, коммит слияния или squash — для merge;
куда переносятся коммиты — для rebase). Есть и перенос по коммитам
(интерактивный rebase) — **Перенести по коммитам...**: список коммитов с
действием для каждого (Pick, Reword, Squash, Fixup, Edit, Drop) и
перестановкой строк. Начатые merge/rebase/cherry-pick можно продолжить,
пропустить текущий коммит (только rebase) или прервать — пункты **Ветка →
Продолжить / Пропустить этот коммит / Прервать слияние или cherry-pick**.

### Разрешение конфликтов

Конфликтный файл открывается двойным щелчком или через контекстное меню
(**Разрешить конфликт...**). Окно показывает три панели только для чтения —
«Наша», «База» (можно скрыть) и «Их» — и снизу редактируемый итог. Кнопки
«Взять нашу», «Взять их», «Взять обе», переходы между конфликтами и счётчик
нерешённых. «Сохранить» пишет итог в рабочую копию и, если конфликтов не
осталось, отмечает файл решённым и закрывает окно.

### Stash

**Локально → Сохранить в stash...** — прячет локальные изменения (можно
включить неотслеживаемые файлы и сохранение состояния индекса). **Применить
stash...** и **Удалить stash...** — из того же меню или из узла «Stash» в
панели «Ветки». `refs/stash` полностью совместим с git.

### Git-Flow

**Инструменты → Git-Flow** (или кнопка «Git-Flow ▾» на панели инструментов)
повторяет SmartGit: **Начать фичу...**, **Начать исправление...**, **Начать
релиз...**, **Начать ветку поддержки...** создают ветку по схеме именования;
**Завершить фичу...**, **Завершить исправление...**, **Завершить релиз...**
сливают её обратно (с выбором merge/rebase/squash, созданием тега версии для
релизов и исправлений, удалением ветки); **Влить develop в фичу...**
переносит свежие коммиты ветки разработки в текущую фичу слиянием или
rebase. **Настроить...** задаёт схему: режим **Full** (фичи, релизы,
исправления, поддержка) или **Light** (только фичи) и префиксы веток; если
Git-Flow в репозитории уже настроен, тот же пункт предлагает изменить
настройки или отключить Git-Flow. Настройки Git-Flow хранятся прямо в
`.git/config` — как у SmartGit.

### Worktree (рабочие копии)

**Репозиторий → Добавить рабочую копию (worktree)...** — каталог, три режима
(новая ветка, существующая ветка, без ветки — detached), точка старта и
флажок «Не заполнять каталог файлами». Каталог по умолчанию подставляется
рядом с репозиторием по имени ветки. **Удалить рабочую копию (worktree)**
спрашивает подтверждение, а при незакоммиченных изменениях — ещё раз, уже
про принудительное удаление. **Удалить устаревшие рабочие копии (worktree)**
сначала показывает список того, что будет удалено. Рабочие копии, созданные
вне приложения (например, из консоли), сами появляются в дереве репозиториев
при открытии родителя.

### Submodules (подмодули)

Подмодули видны в панели «Ветки» вместе с их состоянием. Меню **Внешний
репозиторий → Подмодуль**: **Обновить**, **Инициализировать**,
**Синхронизировать**, **Добавить...** (адрес репозитория, путь в рабочем
дереве, необязательная отслеживаемая ветка), **Удалить...**, **Снять с
регистрации...**, **Сбросить...**. Переключение веток создаёт и удаляет
рабочие копии подмодулей по `submodule.recurse`, а fetch и pull заходят в
изменённые подмодули по `fetch.recurseSubmodules`.

### Bisect

**Инструменты → Найти коммит (bisect)...** — диалог с полями «Хорошая
ревизия, проблемы ещё нет» и «Плохая ревизия, проблема есть». После старта в
строке состояния появляется баннер с числом оставшихся ревизий и оценкой
числа шагов; кнопки «Хорошая» / «Плохая» / «Пропустить» отмечают текущую
ревизию, пока bisect не найдёт первый плохой коммит. Bisect, начатый другим
git-клиентом (или из консоли), Go.Git тоже обнаруживает и показывает тем же
баннером.

### Blame и Investigate

**Кто менял строки** (Blame) — из контекстного меню файла или кнопки
«Кто менял» на панели инструментов: список строк файла с автором, коммитом,
временем и текстом; выбор строки показывает, из какого коммита она пришла, и
может передать выделение в Investigate. **Исследовать** (Investigate,
`git log -L`) — история изменений именно выбранных строк, доступна из списка
файлов, из панели «Изменения» и из Blame; список найденных коммитов можно
остановить кнопкой «Остановить», не дожидаясь конца истории.

## Настройки

**Правка → Настройки...** (или кнопка «Настройки» на панели инструментов)
открывает окно с разделами слева (**Общие**, **Git**, **Учётные данные**,
**SSH**) и полем «Поиск настроек» — оно ищет по названию параметра,
подсказке, названию группы, текущим значениям, ресурсам учётных данных и
хостам SSH. Кнопка «Сохранить» становится активной, только когда что-то
изменено; закрытие с несохранёнными правками переспрашивает.

### Общие

- **Язык и внешний вид** — язык интерфейса (переключается без перезапуска;
  свой язык добавляется одним JSON-файлом в каталог `i18n` рядом с
  `config.toml`), тема (светлая / тёмная / «как в системе», по умолчанию
  меняется вслед за темой ОС) и визуальное представление окна — «Dock-панели»
  или «Боковая панель» (тот же переключатель есть в меню **Окно → Режим
  раскладки**).
- **Интерфейс** — показывать панель инструментов, подписи под значками
  панели инструментов, показывать строку состояния, полное имя автора
  коммита в журнале (вместо сокращённого).
- **Цвета** — свои цвета акцента, фона окна, полей ввода, основного и
  вторичного текста кодом `#RRGGBB`, с образцом и общим предпросмотром у
  каждого поля; пустое поле означает цвет системной темы, кнопка «Сбросить к
  системной теме» очищает все пять сразу.

### Git

- **Получение и синхронизация** — лимит журнала (сколько коммитов
  показывать), автополучение и его интервал в секундах, репозиторий по
  умолчанию для получения и отправки, удаление устаревших внешних веток при
  получении, запрет атрибуции (перед отправкой убирает `Co-authored-by` и
  похожие строки из ваших ещё не отправленных коммитов; коммиты, уже
  оказавшиеся на сервере, не трогаются).
- **Расширенные настройки** (свёрнуты по умолчанию) — глубина обхода
  каталогов для наблюдателя за рабочей копией, стратегия `pull` (merge /
  rebase / ff-only), глубина неполного клона, что делать с локальными
  изменениями, которые мешают переключить ветку (спрашивать каждый раз,
  перенести слиянием, сохранить в stash и переключиться, перезаписать).

Настройки репозитория (**Репозиторий → Настройки репозитория...**) —
отдельное окно на каждый репозиторий: название в дереве, автор коммитов
(`user.name`, `user.email`), remote и стратегия pull по умолчанию,
автоматический fetch — каждое поле можно оставить «Как в настройках», тогда
действуют общие настройки.

### Учётные данные и SSH — см. следующий раздел.

## Учётные данные и хранилище секретов (vault)

Секреты — пароли, токены доступа, приватные SSH-ключи и их пароли — хранятся
отдельно от `config.toml`, в зашифрованном файле `vault.bin`
(XChaCha20-Poly1305), и никогда не записываются в лог или в аргументы
процессов.

### Источник паролей

В разделе настроек **Учётные данные** выбирается, откуда Go.Git берёт
пароли: **Собственное хранилище**, **Системный git (credential.helper)**
(если он установлен и настроен) или **Сначала собственное, затем системный
git**.

### Собственное хранилище

Ключ, которым зашифрован vault, может лежать в одном из нескольких «слотов»,
и не только в одном сразу:

- **Учётная запись Windows (DPAPI)** — по умолчанию на Windows, привязан к
  вашей учётной записи, вопросов не задаёт.
- **Системная связка ключей (Secret Service)** — по умолчанию на Linux, если
  доступен keyring (GNOME Keyring, KWallet, KeePassXC); при первой
  разблокировке keyring может показать своё окно подтверждения.
- **Мастер-пароль** — работает везде, нужен на любом компьютере; надёжность
  пароля (слабый / средний / сильный) видна при вводе. Сразу после создания
  хранилища на Windows и Linux с keyring приложение предлагает сразу же
  задать резервный мастер-пароль на случай, если основной ключ станет
  недоступен.
- **Файл ключа** — только по явному выбору, для Linux без keyring или для
  серверов; защита — права доступа к файлу.

Мастер-пароль меняется в том же разделе настроек: нужно ввести текущий
пароль и задать новый — старый после этого перестаёт действовать.

Таблица «Сохранённые учётные данные» показывает статус каждой записи
(сохранено / требуется авторизация / ошибка) с кнопками «Добавить»,
«Изменить», «Удалить»; «Проверить связь» опрашивает удалённый репозиторий тем
же транспортом, что и получение изменений, и показывает число ссылок на
сервере или причину отказа.

### SSH

Раздел настроек **SSH** — таблица известных хостов и ключей: файл ключа (с
паролем ключа, если он есть), «Использовать ключ по умолчанию» или ключ для
конкретного хоста. «Проверить ключ» читает и разбирает файл, при
необходимости запросив пароль. Неизвестный ключ хоста при подключении
показывается отдельным диалогом — с отпечатком и алгоритмом — и запоминается
в `known_hosts` только после подтверждения; изменившийся ключ хоста
подключиться не даст.

## Горячие клавиши

Общие для главного окна (заданы в коде, не настраиваются):

| Клавиша | Действие |
|---|---|
| F5 | Обновить (то же, что **Вид → Обновить**) |
| F9 | Открыть консоль команд |
| Esc | Выйти из режима коммита / закрыть текущий диалог |

В диалогах: Enter выполняет действие по умолчанию, Esc — отменяет. В поле
сообщения коммита и в некоторых текстовых полях многострочных диалогов
подтверждение — Ctrl+Enter (сам Enter добавляет перевод строки). В окнах
разрешения конфликта и редактора индекса «Записать/Сохранить» дублируется
сочетанием Ctrl+S. В консоли команд (F9) стрелки «Вверх» и «Вниз» пролистывают
историю ранее введённых команд.

## Встроенная консоль

**Инструменты → Консоль команд...** (или F9) — окно с историей команд и
разбором командной строки, как у git. Выполняются те же операции, что и из
интерфейса, но текстом: `status`, `log`, `branch`, `checkout`, `switch`,
`add`, `reset`, `commit`, `diff`, `fetch`, `pull`, `push`, `merge`, `rebase`,
`stash`, `tag`, `remote`, `config`, `submodule` — всё собственным ядром, без
обращения к системному git. Неподдержанная команда сообщает об этом прямо в
консоли.

## Если что-то пошло не так

- **Журнал `gogit.log`** — первое место, куда стоит заглянуть: находится в
  каталоге настроек (см. «С чего начать»), пишется всегда. Если приложение
  начинает занимать заметно больше памяти, в журнал попадает отдельная
  запись с размером кучи, числом объектов, открытым репозиторием и текущей
  операцией — это помогает понять, что именно выполнялось в момент роста.
  Файл ротируется при достижении 5 МБ, старые копии остаются рядом как
  `gogit.log.1`, `gogit.log.2`, `gogit.log.3`.
- **Занятость окна.** Если команда не реагирует, посмотрите на строку
  состояния — вместо молчаливого «Занято» она называет операцию («Занято:
  Отправка») и предлагает её прервать.
- **`GOGIT_PPROF`** — переменная окружения для глубокой диагностики
  производительности: `GOGIT_PPROF=127.0.0.1:6060` включает встроенный
  профилировщик Go (`net/http/pprof`) на указанном адресе. По умолчанию
  выключен; адрес обязан быть на loopback-интерфейсе (`127.0.0.1`,
  `localhost` или `[::1]`) — на внешний адрес профилировщик не запустится.
- **Раскладка панелей сломалась или пропала.** **Окно → Сбросить раскладку**
  возвращает панели на исходные места без переустановки и без потери
  настроек и репозиториев.
- **Настройки не открываются или повреждены.** Файл `config.toml`, который
  не удаётся разобрать, Go.Git не перезаписывает молча: он переименовывает
  его в `config.toml.bad-<дата>-<время>` в том же каталоге и продолжает
  работу с настройками по умолчанию, показав об этом сообщение. Прежние
  репозитории и секреты при этом не теряются — их можно свериться со старой
  копией файла и перенести вручную.
