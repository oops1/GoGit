# Изменения

## 1.5.0 — 2026-09-16

Staging строк и hunk'ов, стэши, обслуживание репозитория, поиск по журналу,
git-flow как в SmartGit, хуки, слияния и rebase, доведённые до поведения git
на нестандартных случаях, более быстрый blame и точный diff, более надёжная
сеть и хранилище секретов.

### Staging и stash

- Строки и hunk'и можно выбрать прямо в панели diff и применить к индексу или
  к рабочей копии — стадия, снятие со стадии и отмена частями файла, а не
  только файлом целиком. Результат сверен с `git apply --cached` на 11 видах
  выбора в обе стороны.
- Stash: сохранение, применение, снятие со стадии и удаление из меню «Правка»
  и из узла «Stash» панели «Ветки»; `refs/stash` и его журнал ссылок
  совместимы с git. Переключение ветки при мешающих локальных изменениях
  предлагает выбор — унести их с собой стэшем, перенести слиянием или
  перезаписать — и запоминает решение.

### Обслуживание репозитория

- Свой `repack`, `gc`, `prune`, `fsck`, `count-objects` и запись
  `commit-graph` — без обращения к системному git. Набор достижимых объектов,
  проверка packfile'ов и файла commit-graph сверены байт в байт с
  соответствующими командами git.

### Поиск по журналу

- Фильтр журнала ищет по изменённому содержимому (`-S`, `-G`, с флажком
  «регулярное выражение») и по пути — второй строкой панели фильтров, поверх
  фильтров по ветке, автору и сообщению из 1.4.0.

### Git-flow

- Полный git-flow в духе SmartGit: кнопка «Git-Flow ▾» на панели инструментов
  и то же меню в «Ветка → Git-Flow» — Start/Finish для Feature, Hotfix,
  Release и Support Branch, Integrate Develop, диалог «Configure…» с
  переключателем Light/Full и окном-вопросом «изменить или отключить», режим
  Git-Flow Light без ветки `develop`. Последовательности команд для каждого
  вида ветки сверены с логом операций SmartGit до хеша.
- Двойной щелчок переключает ветку, контекстные меню ветки и файла повторяют
  SmartGit — включая коммит изменений без предварительной стадии.

### Хуки

- `pre-commit`, `commit-msg`, `post-checkout`, `post-merge`, `pre-rebase` и
  `pre-push` запускаются как отдельные процессы так же, как это делает git —
  на Windows только расширения без суффикса и `.exe`, как в Git for Windows.
  Диалог коммита и push показывает вывод хука и предлагает обойти его.

### Подмодули и bisect

- `.gitmodules` проверяется так же, как `git fsck`; коммит, на который
  переключён подмодуль, учитывается при конфликтах, стадии и checkout, а
  перемещённый подмодуль виден в статусе рабочей копии, как у `git status`.
- Bisect, начатый другим git-клиентом, обнаруживается и показывается баннером
  с возможностью завершить его так же, как `git bisect reset`.

### Слияния и история

- Слияние учитывает `merge.conflictStyle`, diff-атрибуты пути и собственные
  подписи версий в конфликте; переименования каталогов следуют
  `merge.directoryRenames`, а их обнаружение ограничено так же, как у git.
- Merge, cherry-pick, revert, rebase, применение стэша и шаги git-flow
  останавливаются с конфликтом там же, где это делает git — на расщеплении
  переименованного каталога, скрытой замене типа пути и различающихся только
  регистром именах — вместо того, чтобы молча разложить файлы не туда.
- `rerere` различает одинаковые на вид конфликты одного слияния; интерактивный
  rebase сохраняет коммиты, которые были пустыми исходно, и пропускает
  коммиты, уже применённые в базовой ветке, как это делает git.

### Blame и diff

- Blame следует только настоящим переименованиям пути и обходит историю
  очередью по дате — заметно быстрее на длинной истории; добавлены алгоритмы
  `patience` и `minimal` и опция `ignore-cr-at-eol`.
- Diff-атрибуты пути решают, что считать двоичным файлом, и применяются к
  diff'ам коммитов; сравнение деревьев понимает магию и глобы git pathspec.

### Сеть

- SSH-подключение предлагает ключ из хранилища, из ssh-agent или из файла
  identity, с диалогом пароля ключа; читаются `core.sshCommand`, известные
  алгоритмы ключей хоста из `known_hosts` и строки, которые он разобрать не
  может, пропускаются, а при недоступном ssh-agent используется его pipe.
- HTTP-транспорт учитывает прокси, TLS, ограничение скорости и `extraHeader`
  git, `protocol.allow`, отправляет user agent, идёт по редиректу обнаружения
  и умеет откатиться на протокол v0, если сервер не поддерживает нужные
  возможности v2.

### Пароли и хранилище секретов

- Credential-хелперы больше не запускаются как внешние программы: Диспетчер
  учётных данных Windows (форматы generic и wincred) и Secret Service Linux
  (форматы generic и libsecret) читаются напрямую; настройки `credential.<url>`
  применяются с тем же сопоставлением URL, что и у git.
- Мастер-пароль можно сменить, для него предлагается резервный пароль, ошибки
  системного хранилища ключей объясняются; повреждённый `config.toml`
  восстанавливается вместо отказа при старте. В логах маскируются заголовки
  токенов, URL любой схемы, похожие на секреты ключи и составные значения.

### CI

- Оракулы против системного git разделены с юнит-тестами, гонки данных
  проверяются так же по отдельным наборам с кешем сборки на каждый; наборы
  тестов идут параллельно, а дублирующие и перекрытые новым коммитом запуски
  останавливаются; сборка на `main` пропускает наборы, уже пройденные на том
  же дереве в `develop`.

## 1.4.1 — 2026-09-12

- Журнал операции больше не рисует обрывки букв в строке со счётчиком: список

## 1.4.0 — 2026-09-12

Слияния и история: merge, rebase (в том числе по коммитам), cherry-pick, revert,
reset, теги, rerere, blame, история файла, журнал ссылок, сравнение ветвей,
переключение ветки и панель деталей коммита.

### Слияния

- Трёхстороннее слияние на собственном движке: diff3 и zdiff3, переименования,
  смена режима, конфликты «изменено против удалено», виртуальная база для
  истории с несколькими базами. Результат совпадает с `git merge` байт в байт
  на 41 сценарии оракула, включая файлы состояния и записи reflog.
- Режимы ff, no-ff и squash; `MERGE_HEAD`, `MERGE_MSG`, `MERGE_MODE`,
  `AUTO_MERGE` и `SQUASH_MSG` пишутся так, как их пишет git, поэтому начатое
  нами слияние продолжает git и наоборот.
- В приложении: меню «Ветка», «Слить в текущую» в панели ветвей, диалог режимов,
  окно операции, баннер незавершённого слияния с «Коммит…» и «Отменить»,
  «взять нашу/их версию», «отметить решённым», сообщение из `MERGE_MSG` в
  диалоге коммита.
- `rerere`: конфликт запоминается с тем же идентификатором, что у git, решение
  записывается при коммите и возвращается само, когда тот же конфликт
  повторяется; `rerere.autoupdate` ставит решение в индекс.

### История

- cherry-pick и revert с состоянием `CHERRY_PICK_HEAD`/`REVERT_HEAD`,
  продолжением и отменой; пункты в контекстном меню журнала.
- rebase обычный и `--onto`, а также по коммитам: pick, reword, edit, squash,
  fixup и drop. Состояние в `.git/rebase-merge` git-совместимо: прерванный нами
  rebase продолжает git, и наоборот. Диалог выбирает действие для каждого
  коммита и переставляет их.
- `reset` в режимах soft, mixed и hard и по путям, с `ORIG_HEAD` и записью в
  reflog; вызывается из журнала.
- Аннотированные и простые теги: создание из журнала, удаление из панели ветвей.
- blame по истории с переименованиями — строка за строкой совпадает с
  `git blame --porcelain`; история файла с `--follow`; оба окна открываются из
  панели файлов.
- Журнал ссылок ветки с возможностью вернуть ветку на любую запись.
- Сравнение двух ветвей: сколько коммитов только здесь и только там, плюс список
  файлов с различиями.
- Панель деталей коммита: «Информация» (автор, хеш, даты, родители, содержащие
  ветки и теги), «Изменения» и «Файлы».
- Фильтры журнала: по ветке, по автору и по подстроке сообщения — предикатом на
  ленивом обходе истории.

### Ветки и файлы

- Переключение ветки диалогом: локальная ветка или новая от удалённой, сразу со
  слежением за ней.
- Окно «Сравнить файлы»: две стороны, правка и сохранение, навигация по
  изменениям; выбранные в рабочей копии файлы подставляются сами.
- Панели, оторванные в отдельные окна, возвращаются на место при сбросе
  раскладки.
- Журнал операции считает объекты: «Запись объектов: 12 из 35» обновляется на
  месте вместо бесконечного повторения одной и той же строки.

## 1.3.3 — 2026-09-11

Цвета системы, единый вид диалогов, запрет атрибуции и исправления сети.

### Оформление

- Все диалоги красятся одним пакетом стиля: поля, списки и кнопки одного вида,
  главная кнопка залита акцентом, цвета берутся из темы, а не из констант.
- Системный акцент: из `AccentPalette` в Windows и `kdeglobals` в KDE берутся
  те же оттенки, что использует сама система, — светлый для тёмной темы,
  тёмный для светлой. Им красятся выделение, фокус, главные кнопки. Смена
  акцента в системе подхватывается на лету. Фон окна остаётся нейтральным,
  как у приложений Windows.
- Выделенная строка читается при любом акценте: заливка выделения уходит от
  цвета текста.
- Окно «Настройки репозитория» перестроено по макету: разделы с заголовками,
  прокрутка формы, подвал с подсказкой и кнопками.
- Окно «О программе» ужато под содержимое.

### Журнал

- Рядом с автором коммита показываются люди, которых коммит называет в
  трейлерах атрибуции (`Co-authored-by`, `Helped-by`, `Reviewed-by` и
  подобные): в коротком режиме — серыми квадратиками с инициалами, в режиме
  полного имени — через запятую.

### Запрет атрибуции

- Новая настройка в разделе Git, по умолчанию включена. Перед отправкой
  коммиты, которые уйдут на сервер, проверяются: у каждого должны быть автор
  и почта, а трейлеры, называющие других людей, убираются из ваших коммитов.
  Коммиты, которые уже есть на сервере, не трогаются.

### Исправления

- После push и fetch в репозитории, где git уже вёл reflog, не обновлялась
  ветка слежения: коммиты оставались «неотправленными», счётчик ↑N не сходил
  даже после перезапуска.
- После pull журнал не показывал принесённые коммиты до перезапуска: база
  объектов не видела pack, записанный после её открытия.
- Автоматический fetch каждые пять минут падал с «Access is denied», когда
  сервер присылал тот же pack повторно.
- Команда меню, которая зависает дольше восьми секунд, оставляет в журнале
  приложения стеки всех горутин.

## 1.3.2 — 2026-09-08

Исправления двух ошибок, которые мешали работать каждый день.

- Репозиторий, открытый в прошлый раз, снова открывается при запуске. Раньше он
  только подсвечивался в дереве: путь показывался в строке состояния, папки
  раскрывались, но ветки, журнал и рабочая копия оставались пустыми, пока по
  нему не щёлкнешь дважды.
- Панель различий показывает файл, который выбран, а не строку под ним. Когда
  список файлов отфильтрован — по подстроке или по статусу, — строки грида
  больше не считаются номерами в полном списке; файл ищется по пути.

### Под капотом

- `gitcore/merge`: трёхстороннее слияние файла в стилях merge, diff3 и zdiff3 —
  байт-в-байт как `git merge-file`, включая склейку конфликтов, разделённых
  тремя строками и меньше. Основание для слияний в 1.4.0, из интерфейса пока
  не вызывается.

## 1.3.1 — 2026-09-08

Граф коммитов в журнале и значки в меню.

### Граф коммитов

- Колонка графа: дорожки коммитов с точками, переходы между дорожками —
  скруглённой кривой, коммит слияния — кольцом. Цвет закреплён за дорожкой на
  всю её жизнь, палитра общая с значками авторов.
- Основная линия держится левой дорожки: когда две линии сходятся, выживает
  левая, а закрывающаяся уводится в неё переходом — граф не расползается
  вправо с каждым слиянием.
- Ширина колонки считается по дорожкам, которые видны в окне, и
  пересчитывается при прокрутке: под граф не отводится место «на всякий
  случай».
- История обходится так, как это делает git, когда рисует граф: родителя не
  показываем, пока не показаны все его дети. Раньше журнал шёл строго по дате,
  и коммит слияния, сделанный позже своей ветки, открывал дорожку, которая
  оставалась пустой до конца страницы.
- Разделительные линии между строками журнала убраны — они резали дорожки.
- Раскладка дорожек живёт между страницами журнала, поэтому линии не рвутся
  на границе подгрузки; дорожек больше шестнадцати не рисуется, лишние
  схлопываются в крайнюю правую.

### Метки и цвет

- Перед сообщением коммита рисуются метки ссылок: текущая ветка заливкой
  акцентом, прочие локальные — приглушённой, удалённые — серой, теги —
  янтарной. Порядок: текущая ветка, локальные, удалённые, теги.
- Коммиты, которых ещё нет на сервере, рисуются в графе янтарным — и точка, и
  линии. Если удалённая ветка настроена, но push ещё не проходил, локальной
  считается вся история; если удалённых нет вовсе, не красится ничего.

### Значки в меню

- В меню «Репозиторий», «Правка», «Удалённые», «Вид», «Справка» и во всех
  контекстных меню у пунктов появились значки — 28 своих плюс значки тулбара
  для одинаковых команд. У выключенного пункта значок гаснет вместе с подписью.

### Движок

- Поднят до v3.16.10: значок в пункте меню (GG-53) и линии, ломаные и контуры
  `AAShapes` в отрисовке ячейки таблицы (GG-54).

## 1.3.0 — 2026-09-08

Навигация по репозиториям: рабочие копии (worktree), группы перетаскиванием,
контекстные меню и собственные настройки у каждого репозитория.

### Рабочие копии (worktree)

- Реализованы в ядре без системного git: добавление, список, удаление,
  очистка, блокировка и перенос. Git открывает наши рабочие копии, а мы —
  созданные им.
- Меню «Репозиторий» больше не заглушка. «Добавить рабочую копию…» — своё окно:
  каталог с обзором, три режима (новая ветка, существующая ветка, без ветки),
  точка старта и «не заполнять каталог файлами». Каталог подставляется рядом с
  репозиторием по имени ветки и перестаёт подставляться, как только его правят
  руками.
- До запуска проверяются занятый каталог, недопустимое имя ветки, уже
  существующая ветка и ветка, занятая другой рабочей копией.
- «Удалить рабочую копию» спрашивает подтверждение, а при незакоммиченных
  изменениях — второй раз, уже про `--force`. «Удалить устаревшие» сначала
  показывает список, который будет удалён.
- Рабочие копии, созданные вне приложения, сами появляются в дереве под своим
  репозиторием при его открытии.

### Дерево репозиториев

- Репозитории и группы переставляются перетаскиванием: внутрь группы или рядом
  с другим узлом. Рабочие копии остаются при своём репозитории.
- Свёрнутые группы запоминаются между запусками.
- Контекстные меню у дерева и таблиц: открыть, показать в файловом менеджере,
  открыть в терминале, копировать путь; в таблице файлов — ещё индексирование и
  отмена изменений, в журнале — копировать хеш и сообщение.
- Поиск репозиториев: сканирование каталога на `.git`, отметка найденного и
  добавление пачкой.

### Настройки репозитория

- У каждого репозитория своё окно настроек: имя в дереве, `user.name` и
  `user.email`, remote по умолчанию, стратегия pull и автоматический fetch.
- Пишутся git-родные ключи (`user.*`, `remote.pushDefault`, `pull.rebase`,
  `pull.ff`), поэтому системный git видит те же настройки. «Как в настройках»
  удаляет ключ, а не пишет пустое значение.
- Remote по умолчанию и авто-fetch репозитория перекрывают общие настройки.

### Прочее

- Окно «О программе» перерисовано по макету: размеры, отступы и выравнивание
  совпадают с ним попиксельно.
- Фон заголовков панелей приглушён — он больше не забирает внимание у
  содержимого.
- В просмотре коммита видны все его файлы, а вернуться к рабочей копии можно
  заметной кнопкой со значком.
- Нарисованы значки для всех команд меню; показать их в самих меню движок пока
  не умеет (GG-53).

### Исправления

- Пути рабочих копий сравниваются по разрешённым именам: короткое имя
  каталога Windows (`RUNNER~1`) больше не считается другим каталогом.
- Устранена гонка: просмотр различий читал открытую рабочую копию, пока её
  меняли в другом потоке.
- Репозиторий нельзя вложить в репозиторий — реестр проверяет, что новый
  родитель действительно группа.
- Раскрытие репозитория с рабочими копиями показывает его каталоги: заглушка
  убиралась только когда была единственным ребёнком.

## 1.2.0 — 2026-09-07

Окно настроек переделано целиком, появились окно «О программе» и проверка
обновлений.

### Окно настроек

- Единое окно вместо четырёх: слева навигация во всю высоту с иконками
  разделов, справа заголовок раздела и содержимое, снизу «Отмена / Сохранить».
- Окно собрано на штатных возможностях движка: полоса заголовка с тремя
  кнопками окна, поиск прямо в полосе, кнопка «≡» сворачивает навигацию в
  полоску с иконками, и освободившееся место отдаётся содержимому.
- Поиск по настройкам: имя параметра, пояснение, название группы, текущие
  значения, ресурсы учётных данных и хосты SSH; счётчик совпадений у раздела и
  сообщение, когда ничего не нашлось.
- Единая сетка разделов: подписи, поля и серые пояснения выровнены, редкие
  параметры git убраны в сворачиваемую группу «Расширенные настройки».
- Длинный раздел прокручивается, а не растягивает окно.
- «Сохранить» неактивна, пока ничего не изменено; при закрытии с правками
  задаётся вопрос.
- Размер окна меняется: таблицы тянутся, длинные значения обрезаются
  многоточием, ничего не налезает.

### Учётные данные и ключи

- Разделы «Учётные данные» и «SSH» — таблицы со статусом каждой записи
  (сохранено, требуется авторизация, ошибка) и кнопками «Добавить», «Изменить»,
  «Удалить» справа.
- Добавление и изменение — в отдельных окнах, а не в форме под таблицей.
- «Проверить связь» действительно проверяет: опрашивает удалённый репозиторий
  тем же транспортом, что и получение изменений, и показывает число ссылок или
  причину отказа. «Проверить ключ» читает и разбирает файл ключа, при
  необходимости с паролем.
- Выбор источника паролей виден сразу: для собственного хранилища показывается
  путь и способ защиты ключа, для системного git — список помощников.

### Исправления

- Помощник учётных данных системного git находится, даже когда он лежит вне
  PATH: рядом с самим git (`mingw64/bin`, `libexec/git-core`) и в обычных
  местах установки. Раньше на Windows вызов помощника не удавался и приложение
  спрашивало пароль само, хотя git из консоли отвечал молча.

### Прочее

- Окно «О программе»: версия, платформа, архитектура, ядро git и графика,
  ссылки на проект и лицензию.
- Проверка обновлений: пункт в меню «Справка» и автоматическая проверка при
  запуске раз в три дня; неудачная попытка не засчитывается, поэтому следующий
  запуск пробует снова.
- Теги в панели веток сворачиваются в дерево по числам версии, три последних
  остаются на виду.

## 1.1.0 — 2026-09-06

Сеть и секреты. Репозиторий теперь можно склонировать, получать и отправлять
изменения, не выходя из приложения и по-прежнему не используя системный git.

### Сеть

- Транспорт git на чистом Go: pkt-line, side-band, согласование возможностей,
  протоколы версий 1 и 2.
- Smart HTTP и HTTPS с повтором запроса при 401, `git://`, SSH и локальные пути.
- Локальный транспорт читает репозиторий на диске напрямую: клон с соседней
  папки работает без сети и без внешних программ.
- Настоящее согласование объектов по раундам `have`, а не один шаг.
- Запись pack-файлов с дельта-сжатием и потоковый приём с достройкой thin-пака.
- `clone` (полный, bare, по ветке, одна ветка, поверхностный), `fetch`, `pull`
  только перемоткой, `push`, `prune`, управление удалёнными репозиториями.
- `FETCH_HEAD` и файл `shallow` пишутся в формате git.
- `--force-with-lease`: отправка отклоняется, если удалённая ветка ушла вперёд.

### Секреты

- Хранилище `vault.bin`: XChaCha20-Poly1305, ключ содержимого под слотами
  DPAPI (Windows), Secret Service (Linux), мастер-пароль (Argon2id) и файл ключа.
- Учётные данные ищутся по самому длинному совпавшему префиксу адреса.
- SSH: ключи из каталога и из хранилища, ssh-agent через сокет и именованный
  канал Windows, `known_hosts` с подтверждением неизвестного ключа и отказом
  при изменившемся.
- Секреты живут в `[]byte`, зануляются после использования и не попадают в лог:
  движок отдаёт содержимое поля пароля байтами, минуя неизменяемую строку.
- Источник паролей выбирается в настройках: собственное хранилище, помощник
  системного git (`credential.helper`) или сначала своё, потом помощник.

### Интерфейс

- Диалог клонирования с проверкой адреса и выбором ветки.
- Меню «Удалённые» и кнопки Pull, Sync, Push работают по-настоящему: ход
  операции виден в окне с логом, операцию можно отменить.
- Диалоги учётных данных, подтверждения ключа хоста и разблокировки хранилища.
- Страницы настроек «Учётные данные» и «SSH-ключи»: список, добавление,
  удаление, мастер-пароль.
- Авто-fetch по таймеру и расхождение с upstream в панели репозиториев
  и строке состояния.
- Настройки: стратегия pull, удалённый репозиторий по умолчанию, очистка
  исчезнувших веток при получении, глубина клона, источник паролей.
- Значок окна ставится самим приложением, поэтому под Linux он наконец есть.

### Чего нет

Merge, rebase, cherry-pick, revert, reset, worktree, разрешение конфликтов,
построчный stage. Следующим идёт переработанное окно настроек, за ним worktree
и слияния.

## 1.0.0 — 2026-09-05

Первый релиз. Настольный git-клиент для Windows и Linux с собственной
реализацией git на чистом Go: системный git не нужен, CGO не используется.

### Ядро git

- Объекты, свободные и упакованные, дельты, `.idx`, alternates.
- Ссылки: свободные и `packed-refs`, символические, reflog, транзакции с `*.lock`.
- Конфигурация git с `include` и `includeIf`.
- Индекс версий 2, 3 и 4 с cache tree.
- `.gitignore` и `.gitattributes` с общим движком wildmatch.
- Разбор ревизий по правилам gitrevisions и обход графа коммитов.
- Diff: Майерс и гистограмма, определение переименований, unified и stat.
- Статус рабочей копии в семантике `git status --porcelain=v2`, включая
  игнорируемые пути и файлы без изменений.
- Обрыв истории на коммитах из файла `shallow` — журнал работает на клонах `--depth`.
- Операции записи: stage, unstage, discard, commit, создание, переименование
  и удаление веток, переключение ветки.

### Интерфейс

- Док-панели с сохраняемой раскладкой, темы Windows 11, русский и английский язык.
- Дерево репозиториев с группами, рабочими копиями и каталогами рабочей копии.
- Дерево веток с локальными, внешними, тегами и stash.
- Панель файлов с фильтрами по имени, состоянию и каталогу.
- Журнал коммитов с подгрузкой по мере прокрутки.
- Двухпанельный diff.
- Окно длительной операции: бесконечный прогресс, лог действий, отмена.
- Слежение за репозиторием: изменения, сделанные другим git, подхватываются сами.

### Чего нет

Сеть (clone, fetch, pull, push), хранилище секретов, SSH, merge, rebase,
cherry-pick, stash-операции, построчный stage.
