# Go.Git

![Go.Git](social_preview.png)

Бесплатный настольный git-клиент для Windows и Linux. Цель — всё, что можно
сделать с git из консоли, делать через удобный визуальный интерфейс.
Альтернатива платному SmartGit.

- Собственная реализация git на чистом Go: установленный git не нужен.
- `CGO_ENABLED=0`, один исполняемый файл со всеми ресурсами внутри.
- Графический движок [headless-gui/v3](https://github.com/oops1/headless-gui):
  интерфейс описан в XAML, логика на Go, темы Windows 11 (тёмная и светлая, по умолчанию как в системе).
- Док-панели: репозитории, ветки, файлы, diff, журнал коммитов — любую можно
  скрыть, перетащить к другой стенке или отсоединить; раскладка запоминается.
- Локализация: русский и английский из коробки, любой другой язык — один JSON-файл.

## Что уже умеет 1.5.2

**Интерфейс.** Меню и панель инструментов повторяют SmartGit; панель
настраивается в отдельном окне и хранится в `config.toml`. Док-панели:
репозитории, ветки, файлы, diff, журнал коммитов. Встроенная консоль выполняет
подмножество команд git нашим же ядром, без системного git.

**Работа с историей.** Клонирование по HTTPS, SSH, `git://` и с локального
пути; fetch, push, pull и синхронизация; управление remote. Слияние, rebase
(включая интерактивный), cherry-pick, revert, reset, разрешение конфликтов
с выбором стороны и `rerere`. Bisect с шагами good, bad и skip. Журнал
коммитов с графом, постраничной подгрузкой, фильтрами по ветке, автору,
сообщению, изменённому содержимому (`-S`, `-G`) и пути.

**Изменения и индекс.** Панель «Файлы» с состоянием каждого файла, фильтрами,
stage, unstage и discard — целиком, ханками или отдельными строками. Редактор
индекса с тремя сторонами: HEAD, индекс и рабочая копия. Двухпанельный diff
с подсветкой, алгоритмы `myers`, `patience` и `minimal`, поиск переименований,
встроенные драйверы diff из git для 27 языков. Stash с неотслеживаемыми
файлами и сохранением индекса; `refs/stash` совместим с git.

**Ветки и рабочие копии.** Дерево веток с локальными, внешними, тегами, stash
и подмодулями; счётчик расхождения `↑3 ↓1` у ветки со своей внешней; меню «≡»
с сортировками и группировкой. Рабочие копии (worktree), git-flow в духе
SmartGit (Feature, Release, Hotfix, Support, режимы Full и Light),
обслуживание репозитория: `gc`, `repack`, `prune`, `fsck`, `count-objects`,
запись `commit-graph`.

**Подмодули.** `.gitmodules` с относительными URL, init, update, sync, add,
remove, unregister и reset; рекурсия при переключении веток по
`submodule.recurse` и заход в изменённые подмодули при fetch и pull.

**Частичная рабочая копия.** Команды `sparse-checkout` с режимом cone
и частичный клон `--filter=blob:none` с дозагрузкой объектов по требованию.

**Исследование кода.** Blame с переходом по истории, Investigate — история
выбранных строк (`git log -L`) из списка файлов, из diff и из blame. Чтение
`commit-graph` с номерами поколений и фильтрами изменённых путей ускоряет
журнал на длинных историях.

**Сеть и доступ.** HTTP-прокси, TLS-настройки git, `extraHeader`,
`protocol.allow`, протокол v2 с откатом на v0, мелкий клон. Аутентификация
Basic, Bearer, NTLM и Negotiate (Kerberos) — в том числе через прокси
с туннелем CONNECT и с привязкой к сертификату сервера.

**Секреты.** Учётные данные и SSH-ключи в зашифрованном хранилище: DPAPI на
Windows, Secret Service на Linux, мастер-пароль или файл ключа. Читаются
и системные хранилища — диспетчер учётных данных Windows и Secret Service,
без запуска внешних программ-помощников. Неизвестный ключ хоста показывается
с отпечатком и запоминается только после подтверждения.

**Хуки.** `pre-commit`, `commit-msg`, `post-checkout`, `post-merge`,
`pre-rebase` и `pre-push` запускаются так же, как их запускает git; вывод
хука виден в диалоге, его можно обойти.

## Чего ещё нет

Отсоединение панели в отдельное окно средствами системы, матрица
совместимости с разными версиями git и установщики. Порядок работ —
в docs/RELEASE_PLAN.md.

## Сборка

Нужен только Go 1.26.

```bash
make build
```

```bash
go run ./cmd/gogit
```

Windows-бинарь без консоли: `make build-windows`.

## Разработка

```bash
make check
```

Интеграционные тесты совместимости используют системный git как эталон и запускаются
отдельно: `go test -tags oracle ./...`.
